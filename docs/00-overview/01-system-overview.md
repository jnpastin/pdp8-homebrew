# System Overview

## 1. Objective

The goal of this project is to design and build a homebrew computer using discrete logic that is compatible with the PDP-8/e architecture.

Primary target:
- Run OS/8 and associated PDP-8 software

---

## 2. Key Features

- 12-bit architecture
- PDP-8/e instruction set compatibility
- SRAM-based memory system
- Modular PCB-based hardware design
- Backplane-based expansion
- Front panel modeled after PDP-8/I for observability

---

## 3. Compatibility Goals

The system aims to achieve:

### 3.1 Required
- Correct execution of PDP-8 instructions
- Compatible instruction encodings
- Functional support for OS/8
- DMA

### 3.2 Not Required (initially)
- Full DEC hardware replication
- Timesharing support (UF not implemented initially)


---

## 4. System Components (Planned)

- CPU (may span multiple boards)
- Memory subsystem (SRAM)
- I/O subsystem (serial console, paper tape)
- Front panel interface
- Backplane interconnect

---

### 4.1 Control Implementation

The system uses a ROM-based control store.

- Control signals are generated by a control ROM
- Inputs:
  - Major State (MS)
  - Timing State (TS)
  - Instruction Register fields
  - Flags
- Outputs:
  - Datapath control signals
  - Next Major State

All instruction execution behavior is defined by ROM entries, except the few realizations listed in [Control Model §8.4](../04-control/01-control-model.md#84-realizations-outside-the-control-word), chiefly the OPR pass unit, whose stages are selected by IR bits directly.

## 5. Current Status

Completed:
- Repository and documentation structure
- Initial architecture definition
- Register set identified
- High-level bus structure outlined
- Timing architecture defined (TCLK / TSTEP / TP / TS model)
- Major state model defined (FETCH, DEFER, EXECUTE, INTERRUPT, DMA)

Also defined:
- Memory subsystem ([06-memory](../06-memory/README.md))
- I/O subsystem: the external-IOT interface, DMA and its arbitration, and the KL8E, PC8E, and RK8E controllers ([07-io](../07-io/README.md))
- Interrupt and skip coordination ([08-interrupts-and-skip](../08-interrupts-and-skip/README.md))

Not yet defined:
- Front panel ([10-front-panel](../10-front-panel/README.md))
- Backplane and physical design, beyond the limits the timing budget sets ([11-backplane-and-physical](../11-backplane-and-physical/README.md))
- Verification and implementation plans (12, 13)

---

## 6. Known Gaps

The following areas must be defined before hardware design begins:

- Front panel design
- Backplane, connectors, and physical layout

---

## 7. Risks

- Control complexity may increase significantly depending on implementation choice
- Subtle behavioral mismatches (skip, interrupt, indirect addressing) may break OS/8
- Timing design may become complex at higher clock rates

---

## 8. Notes

This document describes intent and direction, not final design decisions.

Many implementation details are intentionally deferred until the behavioral model is fully specified.
