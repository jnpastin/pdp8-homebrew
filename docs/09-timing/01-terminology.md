# Timing Terminology

## 1. Purpose

This document defines all timing-related terminology used throughout the system.

All other timing documents must use these terms consistently.

---

## 2. Clocks

### 2.1 Master Clock (MCLK)

Primary system clock source.

- May be variable frequency
- May be externally provided or internally generated

---

### 2.2 Timing Clock (TCLK)

Clock that drives the CPU timing sequence.

- Derived from MCLK
- All timing progression occurs on TCLK

Note: TCLK is 20 MHz ([Timing Architecture §5.1](./02-timing-architecture.md#51-structure)). How it is derived from MCLK (the MCLK source and the division ratio) is not yet defined.

---

### 2.3 Clock Edge

All timing behavior is defined on:

TCLK rising edge (CLK↑)

---

## 3. Timing Sequence

### 3.1 Timing Step (TSTEP)

A single position in the timing sequence.

Properties:

- Counted within each TS: TSTEP 1 to N, where N is the length of the current TS given by the timing ROM (section 3.5).
- Exactly one TSTEP is active at a time.
- TSTEP advances on each TCLK rising edge, except while halted.
- TSTEP transition logic evaluates the pre-edge TSTEP value.
- At most one TSTEP increment occurs on each TCLK rising edge.

---

### 3.2 Timing Sequence (TSEQ)

The ordered progression of timing steps:

TS1 step 1 → … → step N₁ → TS2 step 1 → … → step N₂ → TS3 … → TS4 step N₄ → repeat

where N₁ to N₄ are the lengths of the four timing states of the current major state (section 3.5).

TSEQ is the fundamental timebase of the system.

While `RUN = 1`, TSEQ wraps from the final TSTEP of TS4 to the first TSTEP of TS1.

While `RUN = 0`, TSEQ is held at the first TSTEP of TS1 and does not advance. Halted-state timing is defined in [Major State Timing §8](./03-major-state-timing.md#8-halted-state-and-console-transactions).

At power-on, TSEQ is at the first TSTEP of TS1 (section 3.4).

---

### 3.3 Console Transaction Timer

A timer, separate from TSEQ, that times one console transaction while the processor is halted.

Properties:

- Runs only while `RUN = 0`.
- Starts when a console command is accepted.
- Advances on TCLK rising edges.
- Ends with exactly one TP, the console TP (`TP_FP`), two TSTEPs wide.
- Does not advance, hold, or modify TSEQ.

### 3.4 Power-On Reset

The power-on reset is the interval, generated by the power-on circuitry, from power application until supplies and clocks are stable. It ends on a TCLK rising edge.

While the power-on reset is active:

- TSEQ is held at the first TSTEP of TS1
- `RUN = 0`, `MS = FETCH`, `HLT_REQ = 0`, and `IOT_TRANSFER` is `NONE`
- the console command latch is loaded with CLEAR, as though the command had been accepted
- the control store and the timing ROM are copied from their EEPROMs into their shadow SRAMs (about 7 ms); the reset ends only after the copy completes ([Control Store Organization §8.1](../04-control/08-control-store-organization.md#81-shadow-copy))
- every value the reset sets is set in both ranks of its register ([Timing Architecture §7.6](./02-timing-architecture.md#76-rule-6--two-ranks))
- `/INITIALIZE` is asserted

When it ends, the console transaction timer runs the latched CLEAR as an ordinary console transaction ([Console Execution §9](../03-microarchitecture/09-console-execution.md#9-clear-operation)). At its TP_FP, every I/O controller and the DMA arbiter enter their initialized states, and AC, L, and IE clear ([System Initialization](../04-control/20-control-output-definitions/02-architectural-control-signals.md#49-system-initialization-initialize)). Controllers act on `/INITIALIZE` only at a TP, and the reset itself has none.

The processor is then halted in FETCH and waits for a console command. Every other register is undefined, including PC, IF, DF, MQ, and `MAPR`; the operator sets the start address with LOAD ADDRESS. This matches the PDP-8/E, which comes up halted and asserts INITIALIZE at power-on, the same signal as its CLEAR key (maintenance manual, volume 1, §3.16).

### 3.5 Timing ROM

The length of each TS, and the width of its TP, are read from the timing ROM, a 32K × 8 device of which 8 address bits are used, the others tied low:

| Address input | Width | Meaning |
|---|---|---|
| `MS_EFF` | 3 | the current major state |
| TS code | 2 | the current timing state |
| `AUTO_INDEX_REQUIRED` | 1 | selects the slow DEFER (Timing Architecture §5.1) |
| `TIMING_MODE[1:0]` | 2 | the speed mode, set by a board jumper (Timing Architecture §5.1) |

`MS` changes only at a TP4, or at the console TP, so during each TS `MS_EFF` names the state whose TS is running.

The ROM gives two values:

| Value | Meaning | Stored as |
|---|---|---|
| N | the length of the TS, including its TP | the last setup step, N − W |
| W | the width of its TP: 2 in a TS that can write memory, otherwise 1 | one bit |

TSEQ counts the TSTEPs of the TS and sets TP after step N − W (section 4.4). After step N the count restarts at step 1 of the next TS.

Every input of the ROM is registered state or a static jumper, so its outputs are stable through the whole TS. They settle before `CW_VALID` enables the comparison.

Like the control store, the timing ROM is an EEPROM shadowed in SRAM at power-on ([Control Store Organization §8.1](../04-control/08-control-store-organization.md#81-shadow-copy)).

`TIMING_MODE` follows the precedent of the PDP-8/E's M8330 timing generator, whose jumper W1 holds it in the slow cycle (PDP-8/E Maintenance Manual, volume 1, §3.17, p. 3-53). It is static: it does not change while the processor runs.

## 4. Timing Pulses (TP)

### 4.1 Definition

A Timing Pulse is the end of its timing state:

TPn is the last W TSTEPs of TSn, steps N − W + 1 to N (section 3.5). W is 2 in a TS that can write memory, otherwise 1.

---

### 4.2 Properties

- Active-high.
- Active for W TCLK cycles, one or two.
- Driven by a flip-flop, never decoded combinationally, so it cannot glitch (section 4.4).
- TP1, TP2, TP3, TP4, and TP_FP are mutually exclusive: they are one signal, named by when it occurs.
- Represents a discrete execution event.

---

### 4.3 Role

TP defines when actions occur.

All state changes are triggered by TP.

| When | One-step TP | Two-step TP |
|---|---|---|
| Leading edge (TP rises) | Registers selected to load capture. | The same, and a memory write starts if `/WR` is asserted. |
| One TSTEP later | (this is already the end) | The memory write ends. Address and data are held for one more TSTEP. |
| End (TP falls) | Registers publish what they captured, and TS changes. | The same. |

Nothing visible changes during TP.

### 4.4 Generation

TP, including TP_FP, is the output of one flip-flop clocked by TCLK:

```text
set:    (TSTEP = N - W) AND CW_VALID
clear:  W TCLK periods later, which also starts step 1 of the next TS
```

While halted, the console transaction timer supplies the step, with N = 9 and W = 2.

TP is the one commit clock:

- Its rising edge clocks the capture ranks. Its falling edge clocks the output ranks and advances TS.
- TPn means the TP that occurs during TSn.
- A register that loads at TPn uses TSn, with its other load conditions, as a synchronous enable on that clock. TS is static throughout TP.
- A clock must not be gated from TP and a TS line. TS changes as TP ends, so the gate could emit a false pulse of the next TP.

---

## 5. Timing States (TS)

### 5.1 Definition

Timing States represent execution phases:

TS1, TS2, TS3, TS4

---

### 5.2 Implementation

Each TS is a run of N consecutive timing steps, N from the timing ROM (section 3.5). The current TS is held in a register as a 2-bit TS code (TS1 = 00, TS2 = 01, TS3 = 10, TS4 = 11) that advances as each TP ends, from TS4 back to TS1. The register drives the control store's `TS_CODE` directly and is decoded into the TS1 to TS4 signals.

The lengths are defined in [Timing Architecture §5.1](./02-timing-architecture.md#51-structure): TS2 is the longest, to accommodate the memory access, following DEC's fast- and slow-cycle design (PDP-8/E Maintenance Manual, volume 1, §3.14, p. 3-48).

---

### 5.3 Properties

- Active-high signals
- Exactly one TS asserted at a time
- Span multiple TCLK cycles
- Decoded from the TS code register (section 5.2). A decoded line may glitch while the code changes at a TS boundary, so it must not be used as a clock or edge

---

### 5.4 Role

TS defines when operations are allowed.

TS does not trigger state changes.

---

### 5.5 Control-Store Settle Time (T_CS)

`T_CS` is the longest time from a TS boundary, or from a change in any control input, to a stable control word: the address-formation logic, one slice-ROM access, and the overlay ([Control Store Organization §5.4.3](../04-control/08-control-store-organization.md#543-correctness-and-timing)). It is an implementation parameter set by the parts chosen.

---

### 5.6 Control Word Valid (CW_VALID)

`CW_VALID` is a registered timing signal that marks when the control word is stable.

- Deasserted at the first TSTEP of every TS and of every console transaction.
- Asserted from a fixed TSTEP of each TS, chosen so that at least `T_CS` has elapsed since the TS began.
- Remains asserted through the end of that TS's TP, or through TP_FP for a console transaction.

`CW_VALID` is generated by a flip-flop clocked by TCLK from the TSEQ position, not decoded combinationally, so it cannot glitch.

---

### 5.7 Write Pulse (/WR_PULSE)

`/WR_PULSE` times every memory write.

- Asserted for the first TSTEP of every two-step TP, and of TP_FP. Not asserted in a one-step TP.
- The output of one flip-flop clocked by TCLK, so both of its edges come from TCLK rising edges and it cannot glitch.
- Reaches memory through at most one driver and one receiver, whose unequal rise and fall delays narrow it, over a terminated line.
- Carries no operation: memory writes only when `/WR` is also asserted ([Memory Timing §4](../06-memory/04-memory-timing.md#4-active-write-window)).

### 5.8 DB Transfer Window (DB_VALID)

`DB_VALID` is the window in which `/DB_READ` and `/DB_WRITE` are presented.

- Asserted from 100 ns (two TSTEPs) into every TS through the end of its TP.
- Generated by a flip-flop clocked by TCLK.
- Opens before `CW_VALID`, because the DB strobes are decoded from `IOT_TRANSFER` and do not wait for the control store. The first 100 ns allow DB to change drivers.

---

## 6. Major States (MS)

### 6.1 Definition

Major States represent instruction-level control flow:

FETCH  
DEFER  
EXECUTE  
INTERRUPT
DMA  

---

### 6.2 Role

MS defines what operation is being performed.

MS does not depend on the timing structure, but it selects it: the timing ROM reads `MS_EFF` to set each TS's length (section 3.5).

---

## 7. Summary

| Term  | Meaning | Polarity |
|-------|---------|----------|
| MCLK  | System clock | — |
| TCLK  | CPU timing clock | — |
| TSTEP | Single timing position | — |
| TSEQ  | Full timing sequence | — |
| TP    | Event trigger | Active-high |
| TS    | Execution phase window | Active-high |
| MS    | Instruction control state | — |
| T_CS  | Control-store settle time | — |
| CW_VALID | Control word valid window | Active-high |
| /WR_PULSE | Memory write pulse | Active-low |
| DB_VALID | DB transfer window | Active-high |
